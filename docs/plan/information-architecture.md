# 정보 구조(IA)

작성일: 2026-04-03  
상태: Draft v1

## 1. IA 설계 원칙
1. 사용자는 대부분 **오늘 기록**을 위해 앱을 연다.
2. 기록 후 바로 **상태/패턴**을 본다.
3. 다자녀 환경에서도 현재 대상 아기를 헷갈리지 않아야 한다.
4. 커뮤니티는 핵심 기록과 분리된 경험이어야 한다.

### 안 2. 기록 중심 단순형

### 최종 추천
**초기 v1은 5탭 구조**를 권장한다.
- 홈
- 기록
- 분석
- 일기
- 더보기

이유:
- 탭 과잉을 줄이면서도 BabyTime 핵심 기능을 커버할 수 있다.
- 성장/공동양육/설정은 “더보기” 아래에서 시작하고, 사용량이 늘면 독립 탭 승격 가능하다.

## 3. 최상위 IA

## 3.1 홈
### 목적
- 현재 아기의 상태를 한 눈에 보여준다.

### 포함 요소
- 현재 선택된 아기 카드
- 마지막 수유/수면/기저귀 시간
- 배고픔/수면/배변 상태 요약
- 오늘 요약 수치
- 빠른 기록 버튼
- 진행 중 타이머 카드
- 리마인더 상태

## 3.2 기록
### 목적
- 모든 활동을 빠르게 입력하고 과거 로그를 확인한다.

### 하위 구조
- 타임라인
- 빠른 기록 패널
- 활동 상세 편집
- 사진 첨부
- 필터/날짜 이동

## 3.3 분석
### 목적
- 기록을 패턴과 지표로 읽는다.

### 하위 구조
- 오늘/주간/월간 요약
- 인터벌
- 패턴 차트
- 수유/수면/배변 통계
- 커스텀 차트

## 3.4 일기
### 목적
- 성장일기와 사진 기반 회고를 관리한다.

### 하위 구조
- 비공개 일기 목록
- 일기 작성/수정
- 사진 갤러리형 보기
- 공개 여부 전환

## 3.5 더보기
### 목적
- 성장, 공동양육, 설정, 커뮤니티를 수용한다.

### 하위 구조
- 성장
- 발달 체크
- 공동양육자 관리
- 아기 관리
- 커뮤니티
- 설정
- 결제/프리미엄

## 5. 화면 간 핵심 관계
- 홈 → 빠른 기록 → 기록 상세 → 홈/타임라인 갱신
- 홈 → 아기 전환 → 모든 탭 데이터 컨텍스트 변경
- 기록 → 분석 → 동일 날짜 범위 기반 drill-down
- 기록/성장 → 일기 → 사진 재사용 가능성 검토
- 공동양육 관리 → 실시간 반영 → 홈/기록/분석 동기화

## 6. IA 상 주의사항
1. **아기 컨텍스트는 항상 최상단에 노출**되어야 한다.
2. 기록 입력은 어떤 화면에서도 1~2단계 내 진입 가능해야 한다.
3. 커뮤니티는 아이 개인 데이터와 혼동되지 않도록 시각적으로 분리한다.
4. 성장/발달은 분석과 가깝지만, 부모에게는 별도 의미가 있으므로 “더보기” 하위 독립 섹션 유지가 좋다.
