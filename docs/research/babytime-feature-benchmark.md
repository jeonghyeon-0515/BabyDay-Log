# BabyTime 기능 벤치마크

작성일: 2026-04-03  
상태: Draft v1

## 1. 조사 기준

### 조사 목적
- BabyTime과 **기능적으로 동등한 육아 앱**을 만들기 위해 필요한 기능 범위를 정의한다.
- 기능을 단순 나열하지 않고, **핵심 도메인 / 차별 기능 / 후순위 확장 기능**으로 분해한다.

### 신뢰성 기준
이번 문서는 아래 **공식/1차 출처**만 사용했다.
- BabyTime 공식 홈페이지
- BabyTime 공식 FAQ
- Apple App Store 공식 페이지
- Google Play 공식 페이지
- Supabase 공식 문서

비공식 블로그, SEO형 비교글, 사용자 재가공 요약글은 배제했다.

## 2. BabyTime의 제품 정체성
BabyTime은 단순 수유 로그 앱이 아니라, 다음 4가지를 결합한 서비스다.

1. **아기 활동 기록 앱**
2. **분석/시각화 도구**
3. **공동양육 협업 도구**
4. **성장일기 + 공개 커뮤니티 플랫폼**

즉, 경쟁 기준은 “수유 기록 가능 여부”가 아니라 다음 질문이다.
> 부모가 하루 육아 운영을 이 앱 하나로 끝낼 수 있는가?

## 3. 기능 벤치마크 상세

- 수면
- 기저귀 교환

- 증상

### 기록 UX 특징
- 최소 터치 입력
- 자주 쓰는 항목은 빠르게 재입력 가능
- 타이머 기반 기록 지원
- 일부 활동은 시작/종료 시각 기록
- 최근 기록 재참조가 쉬운 구조

**“언제 먹였는지 / 얼마나 잤는지 / 패턴이 어떤지 / 발달이 정상 범위인지”를 부모가 빠르게 해석**하게 돕는 데 있다.

### 우리가 구현해야 하는 동등 수준
#### P0
- 일/주/월 통계
- 활동별 인터벌
- 성장곡선

#### P1
- 표준 백분위
- 월령별 발달 체크
- 차트 커스터마이징

## 3.3 공동양육 도메인
공식 KR App Store 설명 기준:
- 공동양육자 추가
- 배우자/조부모/도우미와 함께 기록 공유
- 여러 디바이스 간 동기화

### 제품적으로 중요한 이유
이 기능은 BabyTime의 실사용 체감을 크게 올린다.
예:
- 엄마가 외출 중일 때 아빠가 마지막 수유 시각을 바로 확인
- 조부모/도우미가 기록한 데이터를 부모가 동일하게 확인
- “언제 마지막으로 먹였지?” 같은 전달 비용 감소

### 우리가 구현해야 하는 동등 수준
#### P0
- 공동양육자 초대
- 역할 기반 참여
- 실시간 동기화
- 동일 아이 데이터 공동 편집

#### P1
- 권한 세분화(읽기 전용 / 일부 편집 / 전체 편집)
- 초대 만료/재발급

## 3.8 수익화 도메인
공식 KR App Store 기준:
- 공동양육자 수 늘리기
- 광고 제거

### 해석
BabyTime은 “무료 + 제한 해제형 인앱 구매” 구조다.
즉, 기능 동등성을 목표로 한다면 **과금 포인트 설계**도 제품 범위에 포함해야 한다.

### 우리가 구현해야 하는 동등 수준
#### P2
- 광고 제거
- 공동양육자 확장 플랜
- 구독 vs 일회성 구매 재설계

## 4. 기능 동등성 범위 정의

### P0 — BabyTime 대체재로 느껴지기 위한 최소 범위
- 계정/로그인
- 아기 등록/전환
- 수유/수면/기저귀/건강/병원/성장 로그
- 통계/인터벌/패턴 기본 분석
- 공동양육자 공유
- 자동 백업/복구
- 위젯/리마인더 기본형

### P1 — BabyTime 사용자 만족도와 체감을 맞추는 범위
- 성장일기
- 사진 메모
- Quick Memo
- 표준 백분위
- 월령별 발달 체크
- 다크 모드

### P2 — 확장/플랫폼/수익화 범위
- Apple Watch / Wear OS / Siri
- 공개 커뮤니티
- MusicBox
- 광고 제거 / 유료 플랜

## 5. 우리가 취할 제품 전략
### 선택한 접근
- **화면 복제 우선**이 아니라 **도메인 중심 단계적 동등화** 전략을 채택한다.

### 이유
- BabyTime 유사 앱의 핵심 난이도는 UI보다 데이터 구조다.
- 아기/양육자/이벤트/통계/미디어/권한을 먼저 잘못 설계하면 후반에 거의 전부 갈아엎게 된다.

## 6. 구현 시 반드시 주의할 차이점
1. **공개 커뮤니티는 핵심 로그 기능과 분리해서 운영해야 한다.**
2. **아동 데이터는 매우 민감하므로 비공개 기본값이 원칙이다.**
3. **공동양육은 단순 공유가 아니라 권한/감사 로그가 필요하다.**
4. **통계는 원시 이벤트 저장과 집계 규칙을 분리해야 한다.**
5. **오프라인 사용성과 재동기화 정책이 중요하다.**
