# 육퇴로그 (BabyDay Log)

육퇴로그는 **부모와 공동양육자가 아기의 하루를 기록하고, 패턴을 분석하고, 성장일기까지 남길 수 있는 육아 기록 앱**입니다.

단순히 수유 시간만 적는 앱이 아니라,
- 오늘 아기 상태를 빠르게 확인하고
- 수면/수유/기저귀/건강 기록을 쌓고
- 여러 보호자가 함께 기록을 공유하고
- 성장 변화와 일상을 일기 형태로 남기고
- 공개 일기를 통해 다른 부모의 기록도 참고할 수 있는

**기록 + 분석 + 협업 + 커뮤니티** 중심 앱을 목표로 합니다.

## 핵심 가치
- **빠른 기록**: 육아 중에도 몇 번의 탭으로 바로 입력
- **오늘 상태 확인**: 마지막 수유, 수면, 기저귀 상태를 한눈에 확인
- **공동양육 협업**: 가족이 같은 아기 데이터를 함께 기록하고 공유
- **패턴 분석**: 기록을 쌓는 데서 끝나지 않고 흐름을 읽을 수 있도록 지원
- **성장 회고**: 성장일기와 공개 일기를 통해 시간을 남김

## Skillset
- Flutter
- Supabase
- Realtime / Auth / Storage / RLS

## 주요 기능

### 1. 홈 대시보드
육퇴로그의 홈은 “오늘 아기가 어떤 상태인지”를 가장 빠르게 보여주는 화면입니다.

- 현재 선택된 아기 정보 확인
- 현재 household 요약 확인
- 가장 최근 기록 확인
- 홈에서 바로 주요 생성 흐름으로 이동
  - 프로필 저장
  - Household 생성
  - 아기 생성
  - 기록 추가
- 이후에는 마지막 수유/수면/기저귀 상태, 오늘 요약, 리마인더 상태까지 확장 예정

### 2. 육아 기록 기능
기록 기능은 앱의 핵심입니다. 아기의 하루를 이벤트 단위로 저장합니다.

기록 대상 예시:
- 모유수유
- 젖병/분유 수유
- 이유식
- 수면
- 기저귀
- 유축
- 체온
- 약 복용
- 증상
- 병원 방문
- 성장 기록
- 메모 포함 활동 기록

기록 기능의 방향:
- 최근 기록 빠르게 조회
- 아기 기준 기록 연결
- 활동 타입별 확장 가능한 구조
- 추후 타이머 기반 기록, 빠른 입력 패널, 상세 수정 흐름 확장

### 3. 공동양육 / 가족 단위 관리
육퇴로그는 개인 앱이 아니라 **가족 단위 육아 운영 도구**를 지향합니다.

- Household 생성
- Household 기준으로 아기와 기록을 묶음
- 공동양육자가 같은 household 데이터에 접근
- 이후 확장 예정:
  - 초대 코드
  - 역할 기반 접근 제어
  - 실시간 동기화
  - 가족별 설정 분리

### 4. 아기 관리
아기 정보는 모든 기록과 분석의 기준이 됩니다.

- 아기 생성
- 아기 목록 조회
- 생년월일 / 성별 / 소속 household 관리
- 이후 확장 예정:
  - 다자녀 전환
  - 프로필 이미지
  - 예정일 / 미숙아 여부
  - 성장 기준 연결

### 5. 분석 기능
기록은 쌓이기만 하면 가치가 떨어집니다. 육퇴로그는 기록을 **패턴과 숫자**로 읽게 도와줍니다.

현재 1차 분석 화면:
- 최근 이벤트 수
- 이벤트 종류 수
- 최신 기록 타입
- 최신 기록 시각
- 주요 이벤트 분포

이후 확장 예정:
- 오늘 / 주간 / 월간 통계
- 수유 인터벌
- 수면 패턴
- 기저귀 패턴
- 성장 차트
- 커스텀 차트

### 6. 성장 기록 / 발달 체크
아기의 성장 변화는 육아 기록과 별도로 중요합니다.

예정/설계된 범위:
- 키 / 몸무게 / 머리둘레 기록
- 성장곡선 확인
- 한국 기준 성장 백분위 반영
- 월령별 발달 체크

기준:
- **2017 대한소아청소년과학회 한국 성장도표 기준(`kr_2017`)**

### 7. 성장일기
육퇴로그는 단순 숫자 기록을 넘어서 **기억을 남기는 일기 기능**을 포함합니다.

현재 연결된 흐름:
- 내 일기 목록 조회
- 새 일기 작성
- 공개 범위 선택
  - 비공개
  - household 공유
  - 공개
- 일기 날짜 기록

일기 구조:
- 제목
- 본문
- 아기 연결
- 공개 여부
- 날짜 정보

이후 확장 예정:
- 사진 첨부
- 일기 상세 화면
- 수정 / 삭제

### 8. 공개 일기 / 커뮤니티 피드
v1 범위에는 **공개 일기 기반 커뮤니티 흐름**이 포함됩니다.

현재 연결된 흐름:
- 공개 일기 피드 조회
- 일기 탭에서 공개 일기 하이라이트 표시
- 일기 탭에서 공개 피드 진입

목표:
- 내 일기만 관리하는 것이 아니라
- 다른 부모의 공개 기록을 참고할 수 있게 하고
- 기록 앱에 커뮤니티 맥락을 더하는 것

이후 확장 예정:
- 공개 일기 상세
- 반응/북마크
- 신고/차단
- 커뮤니티 정렬/하이라이트

### 9. 인증
로그인은 한국 사용자 흐름을 우선합니다.

우선순위:
1. 카카오 로그인
2. 네이버 로그인
3. 구글 로그인

현재 상태:
- 인증 상태 조회
- 로그인 진입 구조
- 로그아웃

이후 확장 예정:
- 실제 provider 설정 연결
- 세션 복구
- 첫 진입 분기와 자연스럽게 통합

### 10. 온보딩 / 첫 진입 분기
앱은 시작 시 사용자의 현재 준비 상태를 판단해서 다음 단계로 안내합니다.

현재 분기 구조:
- 비로그인
- profile 없음
- household 없음
- baby 없음
- 준비 완료

즉, 사용자는 앱을 실행하면
1. 로그인하고
2. 프로필을 저장하고
3. household를 만들고
4. 아기를 등록한 다음
5. 본격적으로 홈/기록/분석/일기를 사용하게 됩니다.

## 현재 앱 구조
- 홈
- 기록
- 분석
- 일기
- 더보기

각 탭 상태:
- 홈: 실제 대시보드 연결됨
- 기록: activity 흐름 연결됨
- 분석: 1차 요약 화면 연결됨
- 일기: 목록/작성/공개 피드 흐름 연결됨
- 더보기: 계정/가족/기록 관리 허브 구조 정리됨

## 기술 방향
육퇴로그는 아래 방향으로 개발 중입니다.

- Flutter 기반 모바일 앱
- Supabase 기반 백엔드
  - Auth
  - Postgres
  - Storage
  - Realtime
  - Edge Functions

핵심 설계 원칙:
- 가족 단위 household 중심 구조
- 아기 중심 데이터 모델
- activity event 기반 기록 구조
- 공개/비공개 데이터 분리
- 한국형 인증/성장 기준 우선
